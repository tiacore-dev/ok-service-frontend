# Changelog

## 2026-11-20

- `release-version.sh`: метки образа (`revision`, `version`) читаются через `jq` из `{{json .Image}}`, в том числе форматированного и с ключами по платформам (индекс с provenance-аттестацией). Отсутствующая метка, некорректный JSON или разные значения на разных платформах останавливают `plan`; раньше форматированный JSON блокировал `resume` в production.
- `release-version.sh`: легковесный тег вида `vX.Y.Z` теперь ошибка для всех команд (с именем тега), а не база для следующей версии.
- Автоматические production-релизы из `master`: версия SemVer по Conventional Commits (первый релиз — `1.0.0`), аннотированный тег `vX.Y.Z` и GitHub Release только после проверенного деплоя. Описание — `docs/release-process.md`.
- Production собирает отдельный кандидат `prod-<sha>` с production-настройками; тот же digest получает Docker-тег `X.Y.Z`. Деплой production больше не использует `compose down` и игнорирование ошибок pull: образ скачивается и сверяется по digest до изменений, затем ожидается `healthy`.
- Production-запуски сериализованы; запуски без релизных коммитов не собирают и не деплоят production. dev/stage работают как раньше.
- `docker-compose.yml`: репозиторий образа берётся из `DOCKERHUB_USERNAME` (по умолчанию прежний `gloomylime`).
- Уведомления Telegram/Jira/OpenProject различают: деплой не требуется, деплой не удался, деплой выполнен без публикации релиза, релиз выпущен.
- Изменение для production: на master Docker-тег `<sha>` больше не публикуется, `TAG` в `.env` сервера становится `X.Y.Z`.
- Запуск, назначивший кандидату версию `X.Y.Z`, доводит деплой и публикацию до конца, даже если `master` ушёл вперёд (владение проверяется по digest `prod-<sha>` = `X.Y.Z`, меткам revision/version и истории `origin/master`); запуски без назначенной версии остаются no-op. Ошибка чтения `origin/master` или registry останавливает запуск.
- `X.Y.Z` назначается через `imagetools create --prefer-index=false` (digest кандидата сохраняется) и перепроверяется; build, deploy и release используют одну проверку `release-version.sh plan`.
- Публикация: существующий тег `vX.Y.Z` должен быть аннотированным и указывать на коммит; уже созданный Release — успех без деплоя; недостающий Release создаётся только при `healthy` контейнере с тем же digest.
- Сервер: отказ при изменённых отслеживаемых файлах (с перечнем путей) и при попытке отката на более старую версию; образ скачивается до checkout; в `.env` сохраняется `PREV_IMAGE`; лог указывает, что уже изменено при сбое. Ручное удаление тега `X.Y.Z` из Docker Hub убрано из процедуры восстановления.
