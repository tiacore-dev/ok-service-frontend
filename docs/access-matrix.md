# Матрица доступа

Этот документ фиксирует согласованные правила доступа для фронтенда. При реализации новых действий или изменении существующих ориентироваться на него, а не выводить права по аналогии.

## Обозначения ролей

| Обозначение | Условие |
| --- | --- |
| `ADMIN` | Пользователь с ролью администратора. |
| `MANAGER` | Любой пользователь с ролью менеджера; привязка к объекту или спецификации не требуется. |
| `PL_SPEC` | Пользователь с ролью `PROJECT_LEADER`, указанный прорабом конкретной спецификации. |
| `PL_ANY` | Любой пользователь с ролью `PROJECT_LEADER`, в том числе не назначенный прорабом этой спецификации. |
| `USER_SHIFT` | Пользователь с ролью `USER`, указанный исполнителем конкретной смены. |

Если право выдано `PL_SPEC` или `USER_SHIFT`, фронтенд обязан проверять связь с текущей спецификацией либо сменой. Самой роли недостаточно.

## Общие правила

1. Матрица описывает права интерфейса. Скрытие кнопки не заменяет проверку прав на бэкенде.
2. Техническое право получить данные справочника не равно праву открыть страницу. Например, `USER` может получить данные объекта как часть смены, но не имеет права открыть карточку объекта.
3. Для маршрутов объекта, спецификации, смены и приёмки фронтенд должен проверять право просмотра, а не только скрывать действия на странице.
4. Вложения места показываются только в том контексте, в котором их вернул бэкенд: через смену или спецификацию. Фронтенд не создаёт отдельное правило доступа для предпросмотра или скачивания вложения места.
5. Удаление смены всегда начинается с мягкого удаления. Право на восстановление и жёсткое удаление совпадает с правом на мягкое удаление.
6. Если спецификация имеет статус `Закрыто`, любые изменения спецификации и её вложенных сущностей доступны только `ADMIN`: карточка, статус, работы, материалы, места и приёмки.
7. Если приёмка имеет статус `Документы подписаны`, любые изменения приёмки, включая смену статуса, доступны только `ADMIN`.

## Состояния смены

| Раздел матрицы | Значение |
| --- | --- |
| `Смена` | Создание смены и её наполнение до начала смены. |
| `Смена / согласование` | Начало и завершение смены; после завершения и до согласования — редактирование смены, материалов и записей отчёта. |
| `Смена после согласования` | Действия после согласования смены. |

## Места в спецификации

Место в спецификации — это связь с местом объекта. Редактирования связи не предусмотрено: место можно добавить в спецификацию либо удалить из неё.

| Действие | Разрешено |
| --- | --- |
| Добавление связи | `ADMIN`, `MANAGER`, `PL_SPEC` |
| Просмотр | `ADMIN`, `MANAGER`, `PL_SPEC`, `PL_ANY` |
| Удаление связи | `ADMIN` |

## Места в смене до согласования

Под «редактированием» понимается редактирование примечания к уже добавленному месту. Само место не переименовывается.

| Просмотр | `ADMIN`, `MANAGER`, `PL_SPEC`, `PL_ANY`, `USER_SHIFT` |

## Изменение статусов

| Сущность | Действие | Разрешено |
| --- | --- | --- |
| Работа спецификации | Установить или снять признак «Согласовано» | `ADMIN`, `MANAGER`, `PL_SPEC` |
| Приёмка | Любой статус до `Документы подписаны` | `ADMIN`, `MANAGER` |
